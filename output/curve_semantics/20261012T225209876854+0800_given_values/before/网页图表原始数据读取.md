# 网页图表原始数据读取与拟合

整理：2026-10-12。本文说明图表采集、点配对与拟合；逐回合使用规则见[参数要求](参数细化与六回合期限要求.md)。

## 版本与点配对

每回合重新采集与拟合，版本标明市场、阶段、回合、情境、对象、决策区域和上一期实际投入。历史训练匹配历史曲线及历史状态；本回合缺失时记录缺口，未来曲线仅作为显式情景。

### 用户更正：曲线与销售显示点（2026-10-12）

研发需求乘数记作 `m_R=F_R(R_t;情境_t,R_{t-1})`，运营效率乘数记作 `m_O=F_O(O_t;情境_t,O_{t-1})`。情境与上一期投入共同决定当前响应；相同回合或相同前景不能单独证明两条显示曲线相同。网页横轴若为有效投资，必须另行核验其与当期/上期投入的映射，不能凭旧版 `当期+ρ×上期` 假设解释或重复加入历史影响。

销售图中的价格、一般营销、设计师营销、研发四个需求乘数，分别是当前决策相应输入的函数值。按国家与类别分别保存 `当前输入→显示乘数` 配对并拟合；图中横向位置/权重不能当作当前决策输入，显示乘数不能当作固定系数，也不能当作实际需求标签。单次截图提供四个不同函数各一个显示点；每个函数需要收集该类别的多个输入取值，或读取其完整响应数据。

采样时记录当前完整决策、上一期实际研发/运营投入、国家、情境、区域、时间和显示精度；固定其他条件分别拟合四个函数。研发销售点与生产页研发曲线须先核验关系，不能重复乘入需求。生产曲线跨团队或练习/正式迁移须匹配上期投入，或已有经验证的历史映射；不能直接要求不同历史状态下的原始点相等。

历史拟合参数与成绩保留为对应归档条件下的近似。现有模型的固定ρ及单条曲线共享尚未完成按上期状态改造，本次口径更正不等于已经重训需求/效率模型。

联合使用同回合JSON与SVG时，先配对核验，再合并有增量信息的测量，每个原始点只计一次。训练和留出按点索引同时划分两种表示，防止重复计权和验证泄漏。

回合2实测：研发与运营各200点，SVG还原纵轴与JSON数值的最大差异均为2.22×10⁻¹⁶，即数值精度内一致。SVG为相同数据的渲染，没有新增独立纵轴信息；配对去重后拟合参数与JSON版一致，精度没有提高。SVG的等像素间距是类别轴布局，不证明实际投资数值等间距。

保留JSON完整乘数、标签取整误差及SVG一致性核验，不重复训练。见[联合核验](output/visible_coefficients/20261012_round2_joint/联合核验说明.md)。

原始证据保留于raw，交付仅选所需图表数值；姓名处理按[README](README.md)执行。

## 优先读页面初始化JSON

2026-10-12已在内置浏览器的“决策→生产→计划”页验证：页面内联脚本含 `Chart.create(...)`，其第三个参数为图表JSON。研发与运营曲线各有200个原始乘数，比从SVG像素坐标反推更直接。此方法读取浏览器已收到的数据，不执行页面脚本、不触发Ajax、不修改输入。

1. 使用当前可用的cua浏览器工具；首次调用仅绑定用户指定页面，阅读返回API文档。已有有效绑定时复用。
2. 读取当前AX或DOM，确认网址、市场、回合、页面标题、图表名称。示例网址相同并不证明回合相同。
3. 用文档允许的只读 `tab.playwright.evaluate` 读取DOM中的script文本。不要用eval执行读取的脚本，不读取cookie、账号令牌或后台隐藏状态。
4. 对已观察到的 `Chart.create` 行提取JSON参数，用 `JSON.parse` 解析。格式变化时停止并检查实际文本，不用宽泛正则猜测数据。
5. 保存所需图表JSON、采集时间、实际网址、回合和表达形式；同时记录来源SHA256。SVG可保留用于对照，HTML人员信息不直接复制到报告。

以下代码在cua_repl中运行；`tab`为当前已绑定标签页。只适用于本次观察到的单行调用格式。

```javascript
let scriptTexts = await tab.playwright.evaluate(() =>
  Array.from(document.querySelectorAll('script')).map(s => s.textContent || ''));
let lines = scriptTexts.flatMap(s => s.split('\n'))
  .filter(s => s.startsWith('Chart.create('));
let charts = lines.map(line => {
  let m = line.match(/^Chart\.create\("([^"]+)", "([^"]+)", (\{.*\}), "([^"]+)"\);;$/);
  if (!m) throw Error('图表调用格式变化，请检查原文');
  return {id: m[1], type: m[2], data: JSON.parse(m[3]), container: m[4]};
});
nodeRepl.write(charts.map(c => ({id: c.id, type: c.type, axes: c.data.chart})));
```

## 本页字段

| 图表ID | 含义 | 用于拟合的序列 |
|---|---|---|
| quality.control.chart | 有效研发投资→需求乘数 | 曲线, 复合梁 |
| cost.efficiency.chart | 有效运营投资→效率乘数 | 曲线, 泰国 |
| chart.production.planning | 库存、生产、交付等堆叠图 | 不属于投入响应曲线 |

横轴：`data.categories[0].category[i].label`。纵轴：对应 `data.dataset` 中曲线序列的 `data[i].value`。必须先按seriesname识别，不能假定所有页面的第一序列都有相同含义。

回合效果序列仅有少量非空点，其余为字符串 `"NaN"`，属于缺失绘图标记，不能补零或混入完整曲线拟合。堆叠生产图的dataset还有嵌套层级，不能套用两条曲线的数据结构。

纵轴保存完整数值，但横轴label仍取整至千美元，约±0.5。按标签拟合作为主结果；从0起等间距x只能作为另列的敏感性假设，不能称为平台原始未取整投资值。间距须同时兼容全部标签的±0.5区间，不能直接用两个取整端点线性插值（本次运营图会超出区间）。当前效果点的横轴也属于绘图离散标签，不能据此精确反推历史投入延续比例。

## 拟合与核验

复用既有公式：研发 `a+b*(x+c)**d`，运营 `a+b*x/(c+x)`。验证点数、同索引对齐、有限数值、递增横轴、正乘数与曲线单调性。交错留点检验公式近似，然后全部点拟合最终参数。

该检验只验证图表近似，不验证实际需求；研发延续、运营技术尺度、营销与价格作用以及竞争份额仍需实际数据验证。运营是效率乘数，不直接乘入需求。新回合参数独立另存，历史冻结参数和验证成绩保留。
