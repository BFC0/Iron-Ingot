# 项目结构与文件职责

整理日期：2026-10-13（北京时间）。本文说明目录职责和保存位置；模型状态见[README](README.md)，日志、姓名与交付规则见[任务说明](Cesim_任务要求与当前情况说明.md)。

## 目录分工

```text
cesim/
├── README.md             关键提醒、最新状态、当前问题与导航
├── 项目结构.md            目录与文件导航（本文）
├── code/                 维护中的脚本与代码入口说明
│   └── model_v2/         情境审计、需求、财务和重审流程
├── raw/                  原始网页捕获、图表与预算证据
│   └── cross_market/    跨市场原始捕获
├── sources/              规则文本、用户提供图片等来源材料
├── output/               按任务保存的模型、报告、核验、日志与快照
├── history/              历史说明文档及整理前备份
├── quarantine/           隔离证据；保留事故核验与恢复线索
└── work/                 临时工具、专项核验与本地依赖
```

根目录还保留已被脚本、文档和历史清单引用的 JSON、CSV、Markdown 与 Word 文件。脚本使用 `Path(__file__)` 推导项目位置，并读取固定文件名；历史结果也记录来源路径和哈希，因此本次不搬迁这些文件。`output/` 中的代码快照对应当时运行，维护入口以 `code/` 为准。

## 后续文件放哪里

1. 维护代码放 `code/`；临时核验工具放 `work/`，长期复用时再移入维护目录并检查调用。
2. 新原始捕获放 `raw/`，用户资料与规则材料放 `sources/`；带来源和采集时间，保留原件。
3. 新结果放 `output/<任务>/<北京时间时间戳>/`，先排他创建日志，保存来源、参数、代码快照及检查结果，完成后更新 README 入口。已有采用顺序日志的任务沿用原约定。
4. 历史文件与快照留在原处；避免新增根目录产物或覆盖冻结结果。后续若迁移目录，须同时更新脚本调用、报告链接、来源索引及复现说明，原历史哈希仍保留。

分享范围按[任务说明的姓名规则](Cesim_任务要求与当前情况说明.md)检查，只选已脱敏交付文件；原件和历史副本保留。
