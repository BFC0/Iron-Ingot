# 网页图表原始数据读取与拟合

整理：2026-10-14。本文说明网页读取、图表采集、点配对与拟合；逐回合使用规则见[参数要求](参数细化与六回合期限要求.md)。

## 续采时可复用的网页读取提示

以下方法来自2026-10-14续采及交接时的实际观察，适用于Cesim当前页面结构；控件或工具API变化时先读当前文档与页面，不照抄旧ID。不要输出真名，姓名统一用首字母替代。原始网页可保留，展示与交付须脱敏。

1. **先恢复浏览器绑定，再确认实时状态。** 新对话首次使用`cua_repl`先单独调用`await cua.getState()`，阅读工具返回文档，再按返回的浏览器及标签ID绑定现有内置浏览器标签。没有标签时才从已归档、实际观察过的规范栏目链接打开页面。已有有效绑定时复用，不因新消息重新创建标签。课程市场、本人区域、小组、开放回合、截止时间与结果所选历史市场/回合分别记录；当前页眉“回合4”不能证明结果页也是正式4。
2. **市场与回合选择跨标签共享，采集须独占。** 同平台不同标签、不同对话不能当作选择隔离。交接后重新从规范结果栏目进入，回读当前选择器；不要复用旧页面的事件链接认定归属。每个市场尽量完成所需页面再切换，按[打印优先路径](每回合结束后工作清单.md#1-归档范围与打印优先采集路径)采集；快速教程已有归档，不因续采重复打开。
3. **选择器ID会刷新，先观察后使用。** 切换市场或回合后，用当前DOM读取`select`的ID、value、选中选项及完整options，再用当前可见控件继续操作。`group_select...`、`round_select...`的后缀不是固定ID。每页保存选中标签和value，并交叉核对选项、URL栏目、标题及内容；只改栏目URL不能切换历史回合，也不能只凭请求URL或文件名确认市场。
4. **超时后先回读，不立即重复动作。** 本次打开标签及市场切换曾超时，但页面实际已经打开或切换成功。先查看标签清单或当前选择器再判断是否重试。若工具说明执行上下文已重置，按首次调用规则恢复绑定。操作与完整AX读取合在一次调用容易耗尽超时；导航/选择和结果回读可分开，回读优先返回选择器与必要标题等小对象。不要因超时另建重复标签，也不要把“已执行”写成“已核验”。
5. **完整HTML分块读取并核验长度。** 整段HTML直接返回曾被截断。读取`document.documentElement.outerHTML`时同时返回`html_length`，按每块80,000个JavaScript字符生成`html_parts`，持久化前按原顺序拼接，核对长度、结尾`</html>`及截断标记。80,000是本次分块值，不保证整批输出不截断；输出较大时逐块取得，或在工具允许的运行环境中直接排他保存已读取结果，只返回路径与长度摘要。Python核对JavaScript长度使用`len(html.encode('utf-16-le')) // 2`，不要混用UTF-8字节数。不能把截断片段补成完整HTML。
6. **同页一次性保留所需证据，原件排他保存。** 保存完整HTML、全部数表、可见说明、图表初始化脚本文本及内联SVG，并记录实际URL、采集时间、市场/阶段/回合、选择器options、单位、源行列与团队列编号。原件用新文件名及`wx`/`x`排他创建，生成SHA256；不要覆盖旧冲突页或旧拒绝来源。表头有额外列、重复标签或团队归属未知时保留整行，不能截列、补零或猜归属。数表与保存的HTML应再做对应核对。

浏览器只读取页面已收到的DOM数据；不执行页面脚本、不调用隐藏接口。图表脚本可先归档完整原文，再用既有离线解析器提取字面JSON：历史审计中的`charts()`读取`Chart.create`前三个字面参数，比下面限定单行格式的示例更适合批量归档。[历史解析与身份核验](output/round_close/20261012T221044.031+0800/audit/verify_archive.py)、[续采核验脚本](work/verify_history_resume.py)均保留原始标签、缺失值及舍入精度。

覆盖验收分开记录：网页/打印页数、字段/序列来源、财务等式、图表JSON/SVG同点配对、模型训练范围。页面采齐不能自动关闭配对或建模缺口。打印与网页字段还须核对符号和语义，例如本次市场8机器资本支出及支出总计分别显示正支付额与负现金流，不能直接混用。[本次验收与字段对照](output/round_close/20261014_resume_verified/acceptance/20261014T152737.694032+0800/report.md)保留具体证据及限制。

## 版本与点配对

每回合重新采集与拟合，版本标明市场、阶段、回合、情境、对象、决策区域和上一期实际投入。历史训练匹配历史曲线及历史状态；本回合缺失时记录缺口，未来曲线仅作为显式情景。

### 用户更正：曲线与销售显示点（2026-10-12）

研发需求乘数记作 `m_R=F_R(R_t;情境_t,R_{t-1})`，运营效率乘数记作 `m_O=F_O(O_t;情境_t,O_{t-1})`。情境与上一期投入共同决定当前响应；相同回合或相同前景不能单独证明两条显示曲线相同。网页横轴若为有效投资，必须另行核验其与当期/上期投入的映射，不能凭旧版 `当期+ρ×上期` 假设解释或重复加入历史影响。

销售页价格、一般营销、设计师营销、研发四项需求乘数暂按平台给定数值记录；现有证据不足以认定它们随当前个人决策输入变化，不再据此分别拟合函数。“给定”不代表跨回合或情境不变，须按市场、国家、产品、阶段、回合及情境保存；确切含义、适用范围及其进入需求模型的方式仍待核验。 图中横向位置/权重和纵向相对竞争位置分别保存，不当作实际需求标签，也不未经核验直接替代需求模型系数。

销售页给定数值与生产页投入响应曲线分别处理。正式2手动试验中，个人价格2200保存并重入确认后，四个销售图表点与基准相同；这支持暂按给定数值处理，但不能证明所有投入、回合或情境下均不变化。回合结束后用户要求停止拟合，未生成四函数参数，恢复状态未完成核验，见[试验记录](output/sales_response/20261012_manual_formal2/工作日志.md)。研发销售项与生产页研发曲线的关系仍须核验，避免重复计入需求。生产曲线跨团队或练习/正式迁移仍须匹配上期投入，或已有经验证的历史映射。

历史拟合参数与成绩保留为对应归档条件下的近似。现有模型的固定ρ及单条曲线共享尚未完成按上期状态改造，本次口径更正不等于已经重训需求/效率模型。

联合使用同回合JSON与SVG时，先配对核验，再合并有增量信息的测量，每个原始点只计一次。训练和留出按点索引同时划分两种表示，防止重复计权和验证泄漏。

回合2实测：研发与运营各200点，SVG还原纵轴与JSON数值的最大差异均为2.22×10⁻¹⁶，即数值精度内一致。SVG为相同数据的渲染，没有新增独立纵轴信息；配对去重后拟合参数与JSON版一致，精度没有提高。SVG的等像素间距是类别轴布局，不证明实际投资数值等间距。

保留JSON完整乘数、标签取整误差及SVG一致性核验，不重复训练。见[联合核验](output/visible_coefficients/20261012_round2_joint/联合核验说明.md)。

原始证据保留于raw，交付仅选所需图表数值；姓名处理按[README](README.md)执行。

## 优先读页面初始化JSON

2026-10-12已在内置浏览器的“决策→生产→计划”页验证：页面内联脚本含 `Chart.create(...)`，其第三个参数为图表JSON。研发与运营曲线各有200个原始乘数，比从SVG像素坐标反推更直接。此方法读取浏览器已收到的数据，不执行页面脚本、不触发Ajax、不修改输入。

1. 使用当前可用的cua浏览器工具；首次调用仅绑定用户指定页面，阅读返回API文档。已有有效绑定时复用。
2. 读取当前AX或DOM，确认网址、市场、回合、页面标题、图表名称。示例网址相同并不证明回合相同。
3. 用文档允许的只读 `tab.playwright.evaluate` 读取DOM中的script文本。不要用eval执行读取的脚本，不读取cookie、账号令牌或后台隐藏状态。
4. 对已观察到的 `Chart.create` 行提取JSON参数，用 `JSON.parse` 解析。格式变化时停止并检查实际文本，不用宽泛正则猜测数据。
5. 保存所需图表JSON、采集时间、实际网址、回合和表达形式；同时记录来源SHA256。SVG可保留用于对照，HTML人员信息不直接复制到报告。

以下代码在cua_repl中运行；`tab`为当前已绑定标签页。只适用于本次观察到的单行调用格式。

```javascript
let scriptTexts = await tab.playwright.evaluate(() =>
  Array.from(document.querySelectorAll('script')).map(s => s.textContent || ''));
let lines = scriptTexts.flatMap(s => s.split('\n'))
  .filter(s => s.startsWith('Chart.create('));
let charts = lines.map(line => {
  let m = line.match(/^Chart\.create\("([^"]+)", "([^"]+)", (\{.*\}), "([^"]+)"\);;$/);
  if (!m) throw Error('图表调用格式变化，请检查原文');
  return {id: m[1], type: m[2], data: JSON.parse(m[3]), container: m[4]};
});
nodeRepl.write(charts.map(c => ({id: c.id, type: c.type, axes: c.data.chart})));
```

## 本页字段

| 图表ID | 含义 | 用于拟合的序列 |
|---|---|---|
| quality.control.chart | 有效研发投资→需求乘数 | 曲线, 复合梁 |
| cost.efficiency.chart | 有效运营投资→效率乘数 | 曲线, 泰国 |
| chart.production.planning | 库存、生产、交付等堆叠图 | 不属于投入响应曲线 |

横轴：`data.categories[0].category[i].label`。纵轴：对应 `data.dataset` 中曲线序列的 `data[i].value`。必须先按seriesname识别，不能假定所有页面的第一序列都有相同含义。

回合效果序列仅有少量非空点，其余为字符串 `"NaN"`，属于缺失绘图标记，不能补零或混入完整曲线拟合。堆叠生产图的dataset还有嵌套层级，不能套用两条曲线的数据结构。

纵轴保存完整数值，但横轴label仍取整至千美元，约±0.5。按标签拟合作为主结果；从0起等间距x只能作为另列的敏感性假设，不能称为平台原始未取整投资值。间距须同时兼容全部标签的±0.5区间，不能直接用两个取整端点线性插值（本次运营图会超出区间）。当前效果点的横轴也属于绘图离散标签，不能据此精确反推历史投入延续比例。

## 拟合与核验

复用既有公式：研发 `a+b*(x+c)**d`，运营 `a+b*x/(c+x)`。验证点数、同索引对齐、有限数值、递增横轴、正乘数与曲线单调性。交错留点检验公式近似，然后全部点拟合最终参数。

该检验只验证图表近似，不验证实际需求；研发延续、运营技术尺度、营销与价格作用以及竞争份额仍需实际数据验证。运营是效率乘数，不直接乘入需求。新回合参数独立另存，历史冻结参数和验证成绩保留。
