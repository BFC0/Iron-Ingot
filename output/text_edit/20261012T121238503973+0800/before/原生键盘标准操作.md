# 个人决策修改标准操作

适用：Cesim个人区域中的文本数值框。原生键盘方式已在泰国需求预测字段验证；其他文本框首次使用时须完成同样核验。下拉框等控件不套用本流程。

## 操作前

1. 通过`cua.getState()`找到当前标签页，绑定并阅读返回文档。已有有效绑定时复用，不反复绑定。
2. 获取最新AX状态，核对市场、回合、截止时间、个人区域、字段名称、单位和原值。记录基准快照及修改目的。
3. 从**本次AX状态**定位目标输入框编号。编号每次可能变化，不复用历史示例中的151。

## 原生输入

以下每行在`cua_repl.js`中**单独调用**，工具超时设置60秒；等待每一步返回后再进行下一步，避免多步合并导致中途超时。`cesim`为已绑定标签页，`fieldIndex`为最新观察得到的输入框编号，`newValue`为已授权且单位正确的字符串。

```javascript
await cesim.click(fieldIndex);
```

```javascript
await cesim.pressKey(null, 'ControlOrMeta+A');
```

```javascript
await cesim.typeText(null, newValue);
```

```javascript
await cesim.pressKey(null, 'Return');
```

全选四步之间不要切换标签页或点击其他控件。若焦点丢失、用户介入或任一步超时，先重新观察当前值与焦点，再决定重试或恢复；不要在未知状态继续输入。必要时截图确认全选。原生键盘按回车已验证；用户手动点击空白处也可保存，但此前自动失焦未验证成功，不把它作为标准成功路径。

## 保存验收

1. 观察输入值及相关派生字段，确认计算已更新。某些字段不影响当前预算，不能只以预算不变判失败。
2. 进入“决策列表”，确认新值在自己的个人列。按用户2026-10-11明确规则，其他组员在各自个人列的修改不会影响本人的决策及预算数据，不能仅凭其他列变化判定保存失败或停止试验；不向其他成员列或小组列写入。若本人列、所选区域或小组方案变化，重新核验。
3. **重新进入原输入页**，确认新值仍在。输入框、个人列和重入回读必须一致。
4. 归档输入后的快照、决策列表、重入快照及截图，记录时间、回合、区域、字段、单位、原值、新值、输入方式和核验结论。需要验证模型时另存该组完整相关预算。

只有上述核验完成，才标记“已保存”。调用未报错或输入框显示新值都不够。若是临时试验，结束后按同样步骤恢复**试验前最新基准**；用户明确要求保留的新值应保留。恢复不成功时停止后续扰动并报告当前状态。个人保存不等于小组提交。
