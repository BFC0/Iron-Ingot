# 每回合结束后工作清单

更新：2026-10-12（北京时间）。适用于正式第t回合截止结算后的复盘与交接，t为1至6。结果尚未公布时，先归档截止决策与冻结预测，将结果相关事项标记“等待公布”；截止或保存决策本身不代表已取得实际结果。

总顺序：**确认结算 → 归档实际与最终决策 → 核验数据 → 评分原冻结预测 → 分析偏差 → 更新模型 → 结转状态 → 核验下一回合前景 → 交付复盘与交接**。正式6结束后进入终局核验。

每次执行先在`output/round_close/<北京时间时间戳>/`排他创建工作日志，记录课程、市场、阶段、回合、团队、采集时间、授权范围和进行中状态。完成时追加验收；旧日志、证据和模型不覆盖。不要输出真名，姓名统一用首字母替代。

## 逐项执行清单

| 顺序 | 应做的事 | 必须保存的产物与完成标准 |
|---:|---|---|
| 1 | 确认本回合确已结算，实际结果已发布；核对课程、市场、正式回合及本组身份，记录下一回合状态和截止时间 | 结算与选择证据。逐页核对实际选择和结果标题；不能只凭文件名或旧网页状态确认回合。未公布则标记等待，不把预算当实际。 |
| 2 | 归档本组最终生效决策、实际结果、回合前景与曲线，以及同编号市场内各竞争组的可见实际决策和结果 | 原始快照/附件及来源清单、时间、单位、哈希。覆盖国别需求、销量、价格、营销、研发、运营、生产、效率、库存、订单和财务三表等可见项；不可访问项单列。按授权范围采集其他市场，各市场独立定位。实际生效方案无法取得时记录缺口，不用个人草稿冒充。 |
| 3 | 核验结构化数据及分类 | 唯一键包含市场、阶段、回合、团队、国家、类别；需求、销量、玩家预测、预算和模型预测分开。检查缺失、重复、单位、数量守恒、财务平衡及累计值；按显示精度保留误差，不强行改原始数字。保留原冻结模型、预测、输入和最终方案对应关系。 |
| 4 | **先评分原冻结预测，再接触重训** | 用Python生成原预测与实际逐项对照、误差和适用范围。需求按国家比较份额及绝对需求，销量、效率、利润、现金等只评分实际已冻结的对应项。缺预测或最终方案不同则注明不可直接评分，不事后补造事前预测。使用已实现对手或行业总量的条件回溯另列，不能并入事前成绩。 |
| 5 | 分析偏差与经营结果 | 区分决策变更、行业总量、竞争份额、供给限制、效率、成本、融资税费、情境变化及数据精度。对照“模型预测—平台预算—实际”时分别解释口径；销量不足不自动当需求不足。解释当期利润、累计收益、现金及债务变化，不能用现金增长替代收益。原因只能作为有证据支持的诊断，关联不冒充因果。 |
| 6 | 根据新增证据更新参数与模型，复核20项问题 | 将新实际标签加入对应市场/情境的数据版本；国别需求分别研究，投入和行业总量的未识别项继续保留。历史回算选历史回合曲线，不用下一回合曲线改写旧评分。保存新代码、来源哈希、训练键、截止点、参数、训练内选参及留出检查，与旧模型并列；只有通过适用范围和验收才切换当前版本。逐项记录问题关闭证据，未关闭项写下一项所需资料。 |
| 7 | 将本回合期末状态结转为下一回合期初，逐字段核对 | 保存期末—期初对照及来源。现金、长短债、应收应付、库存数量与价值、机器厂房及待生效投资、人员、税亏、研发运营持续状态、订单承诺按真实规则衔接。区分余额与当期发生额；上期收入和费用不原样带入。未知存量和时点保留未知；累积指标独立核算。练习期末不能作为正式1期初。 |
| 8 | 若t小于6，读取并核验下一回合前景五部分及新曲线 | 需求、大客户订单、生产、货币、财务逐项保存当前来源、有效期及变化。重新采集下一回合研发/运营等曲线，JSON与SVG同点配对去重；为下一回合建立对应版本并核验模型实际选用。缺失时明确缺口，不静默沿用旧值。上期未来提示保留并核查是否生效；招标、中标、交付、回款分别跟踪，普通销售与订单避免重复计入。 |
| 9 | 若t小于6，交付复盘与下一回合建模输入 | 交付实际摘要、冻结评分、偏差分析、模型版本、期初状态、当期前景、20项问题更新及待办。下一回合只比较t+1至正式6，剩余6−t回合；此前已实现累计收益保留为共同基准。未知未来收益不补零，不增加未经核验终值。交接通过后再进入下一回合候选比较。 |
| 10 | 追加验收并更新项目入口 | 记录完成、失败、等待和数据缺口；检查原件及冻结文件未被覆盖、来源可追溯、交付数值一致、链接有效和首字母脱敏。更新README当前回合、最新产物、适用模型及未解决问题，保留历史结论。明确哪些结果只是条件验证。 |

## 状态结转中必须单独核验的事项

- **研发与运营：**上一回合实际投入与完整持续存量分开；历史ρ或有效投入代理不能自动当成已验证存量。营销延续同样须有依据。
- **投资与人员：**机器/厂房支付、交付、生效、产能衰减和折旧分别核对；人员期末数量、自然离职、招聘与解聘时点分别核对。
- **订单与库存：**结转未交付承诺和库存数量、账面价值；记录订单报价、币种、交付期、收款及履约条件。数量为零须有来源，缺失不能补零。
- **债务与税亏：**长短债本金、利率、利息、还款及税亏余额分别核对。还本不能直接当费用，利息不能与本金重复扣除；亏后转盈和自动短贷仍需实际规则或有效样本支持。

## 正式6结束后的单独分支

执行第1至6项及第10项；第7项改为保存正式6真实终局状态，第8至9项改为终局复盘，不创建正式7决策或收益预测。

1. 核验正式6当期结果、累计收益、平台成绩和可见排名，记录计分口径及来源。若目标指标与平台成绩不同，分别报告，不擅自换目标。
2. 保留期末现金、资产、债务、库存、税亏、投入存量和未交付订单，按已核终局规则处理；未知计分项单列，不自动变现、清债或赋予终值。
3. 汇总六回合实际决策、事前预测、实际结果与每次模型更新，报告累计误差、有效改进及仍未验证机制。封存代码、输入、模型、报告和来源哈希，更新最终问题清单。

## 每回合最小交付包与交接门槛

每次产物集中在本次独立目录，至少包含：工作日志与来源清单、最终决策与实际结构化数据、原冻结预测评分、偏差复盘、新旧模型说明、期末/下期期初对照、下一回合前景和曲线版本清单、问题与缺口及验收记录。未产生某项时记录原因；正式6使用终局状态与最终复盘替代下一回合资料。

只有身份、类别、来源和关键状态核验通过，模型范围及参数版本明确时，才进入依赖这些资料的候选比较。未解决项可继续做不依赖它们的研究；不能拼出完整利润或六回合最优结论。流程记录完成不表示自动采集、曲线选择、财务分支和状态结转代码已实现。

本清单不恢复助手推荐值填写或小组提交授权。规则与目标见[项目总览](README.md)、[参数细化与六回合期限要求](参数细化与六回合期限要求.md)；当前机制缺口见[20项核验报告](output/issues_review/20261012T112446993158+0800/report.md)。
